# Blackbook VPS deployment

Hosting is paused. Resume only when Jonathan approves and supplies access to a VPS. The scripts target Ubuntu 24.04 x86_64 with an `ubuntu` SSH user. Use an authorized deploy key, verify the host fingerprint before transferring credentials, and ensure SSH password and root login are disabled. The host bootstrap limits public application access to zero ports; SSH is the management exception.

1. Install the host bootstrap, then run it as root. Install the start wrapper and systemd service as root-owned files at the paths used in the service. Update and enable the OS security updater. In the repo use latest merged main, not a feature branch awaiting review.
2. Install a release by streaming a gzipped git archive of only the web directory and assets/<page-id>/manifest.json paths into install-release.sh with the full commit SHA. Do not include backups, clipped data, dot-env files or local data directories. Verify the build passed before starting the unit. Keep the previous release path for rollback; do not duplicate the app data.
3. Create encrypted systemd credentials via SSH stdin (systemd-creds encrypt --with-key=host --name=<name> - /etc/blackbook/<name>.cred; root umask 077). Use the authorized Notion integration and a unique strong owner password. Never send passwords in chat, shell arguments, or logs. Enable the Blackbook service on boot.
4. Enroll the server in Jonathan's personal Tailscale tailnet via the owner login link from tailscale up. Use hostname blackbook and request no DNS override on the server. Enable MagicDNS and HTTPS if needed, keep Funnel off, and verify the tailnet ACL restricts Blackbook access to Jonathan. For a dedicated server, confirm a durable node key policy. Run tailscale serve --bg --https=443 http://127.0.0.1:3000 and verify the status says tailnet-only.
5. Check public access to the app and the backend is closed, HTTPS without app credentials returns 401, and Jonathan's authenticated Explore returns the live catalog. Keep the live Notion token off the client. Check journal and sync status for startup and the next automatically scheduled run; verify re-used embeddings, persistent state across restart, and confirm services and Serve resume on reboot. Send the private URL to Jonathan.
